⚡ Nexu — Session Recap

Three big things landed this session. Here's what changed and why.

1. Fixed a Crash That Broke Every Recording

BUG  stt.py had a subtle ordering bug — the PyAudio instance was terminated before the WAV file was written, so get_sample_size() ran on a dead object and threw. Every voice command was silently crashing before reaching the AI.

BEFORE (broken): record → close audio → ⚠️ audio.terminate() → get_sample_size() ← CRASH AFTER (fixed): SAMPLE_WIDTH = pyaudio.get_sample_size(paInt16) ← captured once at module level record → close audio → audio.terminate() → wf.setsampwidth(SAMPLE_WIDTH) ← no crash

Fix: Moved get_sample_size() to module level as a constant SAMPLE_WIDTH, so it's computed before any PyAudio instances are created or destroyed.

2. Local STT via faster-whisper (finally wired up)

FEATURE  The code for local speech-to-text was already written but never usable because faster-whisper was missing from requirements.txt. Now it's there.

How it works

speech_to_text() │ ├── record_audio() ← PyAudio, silence-detection, WAV │ └── transcribe(path) │ ├── _transcribe_local() ← faster-whisper "tiny" (1.5GB RAM) │ └── confidence > 0.3? ─── YES → return text (instant, offline) │ └── _transcribe_groq() ← Groq Whisper API fallback └── cloud, slower, needs internet

The fallback chain is already built: local first, only go to Groq if confidence is low. The banner now shows the actual provider at startup.

3. Smarter Memory — AI-Powered Fact Extraction

FEATURE  The old memory system was pure keyword search (FTS5). "My favorite color is blue" would never match "what color do I like." Now the AI itself extracts structured facts after each conversation.

Architecture

User: "My favorite color is blue" │ ▼ AI responds + saves to FTS5 (conversation history) │ ▼ ┌─ background thread ──────────────────────┐ │ _extract_facts(user_text, assistant) │ │ │ │ │ ▼ │ │ LLM prompt: │ │ "Extract facts as JSON lines" │ │ │ │ │ ▼ │ │ {"key": "favorite_color", "value": "blue"} │ │ │ │ │ ▼ │ │ memory.store.save("favorite_color", "blue") │ └──────────────────────────────────────────┘ │ ▼ Next session — system prompt includes: "Facts I know about the user: favorite_color: blue" User: "What color do I like?" │ ▼ AI reads facts directly → "Blue!" ← no search needed

Guard rails

  • Only extracts from substantial exchanges (≥3 user words, ≥5 assistant words) — ignores greetings
  • Deduplicates — skips re-extraction if same text pair was already processed
  • Global lock (_EXTRACTING) — only one extraction runs at a time
  • Injects at most 30 most recent facts into the system prompt (previously injected all facts, unbounded)

4. Bonus: Wake Word — How It Works

WAKE WORD  You asked about this — here's the full picture.

Nexu uses OpenWakeWord, a tiny offline neural network that runs in ~100ms on CPU. No cloud, no API key, no microphone data ever leaves your computer.

Flow

Nexu starts │ ▼ WakeWordDetector.__init__() │ ├── openwakeword.Model(inference_framework="onnx") │ └── loads ~5MB ONNX model (trained on "hey jarvis" / "hey mycroft" etc.) │ ├── PyAudio stream (16kHz, mono, 1280-byte frames) │ ▼ _listen() loop: while running: data = stream.read(1280) pcm = struct.unpack("h" * 640, data) prediction = model.predict(pcm) for name, score in prediction.items(): if score > 0.5: callback() ← starts voice recording

Mapping

The code maps casual keywords to built-in OpenWakeWord models:

"nexu"→"hey_jarvis" model
"jarvis"→"hey_jarvis" model
"mycroft"→"hey_mycroft" model
"rhasspy"→"hey_rhasspy" model

Detection threshold: Score > 0.5 triggers the callback. The model outputs per-frame scores (roughly 0–1), and a clean "hey jarvis" utterance typically scores 0.7–0.9.

It runs on the CPU using ONNX Runtime — no GPU needed, ~100ms per prediction, ~10% CPU on an i5. When no wake word is active, it's not loaded at all (zero CPU).
